# Selection Fix Attempt Log

## Problem Summary

xterm.js selection in Obsidian shows a **"ghost" duplicate** — a full-width blue rectangle 2–3 lines above the real character-level selection. The ghost is **browser DOM selection** (the browser selects DOM block elements across the full terminal width), while the real selection is **xterm.js internal SelectionManager** output (character-precise, separate overlay).

## Root Cause (FINAL — attempt #16)

**Obsidian global CSS overrides `position` properties on xterm.js v5 DOM renderer elements.**

xterm.js v5 DOM renderer relies on precise CSS positioning:
- `.xterm-screen` must be `position: relative` — creates containing block for absolutely-positioned children (`.xterm-selection` overlay)
- `.xterm-helpers` must be `position: absolute; top: 0` — must NOT occupy normal flow space

Obsidian's global stylesheet (`app.css`) resets these to `position: static`. This causes:
1. `.xterm-selection` layer positions relative to `workspace-leaf-content` (nearest positioned ancestor) instead of `.xterm-screen` → **85px vertical offset** between selection overlay and text rows
2. `.xterm-helpers` occupies 36px of normal flow space → pushes `.xterm-rows` down, creating additional 36px misalignment

The ghost was xterm.js's own selection divs rendered at correct coordinates WITHIN the selection layer, but the selection layer itself was positioned at the wrong screen position (85px above the text). This produced a "ghost" — a visual duplicate of the selection at an offset position.

**Proof via CDP diagnostics:**
- Before fix: `selectionRect.top` = 490, `rowsRect.top` = 575, **diff = -85px**
- After fix: `selectionRect.top` = 538, `rowsRect.top` = 538, **diff = 0px**
- `xterm-screen` computed position went from `static` → `relative`
- `xterm-helpers` computed position went from `static` → `absolute`
- Screenshot 12: single selection group (Y=598-657, 60px tall), no ghost above

**Fix (styles.css):**
```css
.terminal-view-content .xterm-screen {
  position: relative !important;
}
.terminal-view-content .xterm-helpers {
  position: absolute !important;
  top: 0 !important;
}
```
