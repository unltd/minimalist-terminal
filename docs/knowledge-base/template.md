# Template

Файлы в `docs/knowledge-base/` описывают неочевидные проблемы и решения, найденные при разработке Obsidian Terminal.

## Формат имени файла

```
yyyy-mm-dd--<краткий-ключ-проблемы>.md
```

Дата — когда проблема была **обнаружена**. Ключ — 2-5 слов через дефис, на английском.

## Формат содержимого

```markdown
# <Краткое название проблемы>

**Дата:** YYYY-MM-DD
**Статус:** resolved | worked-around | open
**Связано:** [[other-problem-key]], [[another-key]]

## Симптомы

Что наблюдалось: конкретные проявления, сообщения об ошибках.

## Причина

Корневая причина. Почему это происходит именно в Obsidian.

## Решение

Как починили. Код, CSS, конфигурация.

Если воркэраунд — почему полное решение невозможно.

## Ссылки

- Ссылки на issues, форумы, документацию
- Ссылки на похожие находки в этом KB

## Как найти в коде

Где смотреть: файлы, строки, ключевые слова для grep.
```

## Когда добавлять

- Любая проблема, на решение которой ушло >15 минут
- Неочевидное поведение Obsidian API
- Конфликты с Obsidian CSS/темой
- Особенности Electron, влияющие на плагин
- Баги в зависимостях, требующие воркэраунда

## Правила

- Один файл — одна проблема
- Если проблема пересекается с другой — ссылка `[[key]]` в секции **Связано**
- В **Ссылки** — URL на GitHub issues, форум Obsidian, блог-посты
- **Как найти в коде** — конкретные grep-команды или пути к файлам
