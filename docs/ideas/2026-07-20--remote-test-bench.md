# Remote Test Bench Harness

**Created:** 2026-07-20
**Status:** idea
**Effort:** L
<!-- **Related:** [[2026-07-20--cross-platform-testing]] [[2026-07-20--mvp-test-plan]] -->

## What

Расширить текущий тестовый фреймворк так, чтобы к нему можно было подключать удалённые тестовые стенды — другой компьютер по сети или виртуальную машину. Тесты запускаются локально, но исполняются на удалённой машине (или наоборот: оркестратор на хосте, исполнение на стендах).

## Why

Сейчас тесты работают только локально на macOS через CDP к локальному Obsidian. Это блокирует кросс-платформенное тестирование:
- Нет физического доступа к Windows-машине
- Нет Linux-окружения с Obsidian
- Невозможно гонять тесты на нескольких платформах параллельно

Remote test bench решает это: тесты пишутся один раз, запускаются на любой подключённой машине.

## Rough sketch

Модель: **оркестратор (локально) + агенты (на стендах)**.

```
┌─────────────────────┐     ┌─────────────────────┐
│   MacBook (host)    │     │  Windows VM / PC    │
│                     │     │                     │
│  Gauge runner       │────▶│  CDP agent          │
│  Test orchestrator  │     │  Obsidian + plugin  │
│                     │     │                     │
└─────────────────────┘     └─────────────────────┘
         │                           │
         │     ┌─────────────────────┘
         │     │
         ▼     ▼
┌─────────────────────┐
│   Linux VM / PC     │
│                     │
│  CDP agent          │
│  Obsidian + plugin  │
└─────────────────────┘
```

Компоненты:
1. **Test orchestrator** — локальный Gauge + pytest, который вместо прямого CDP-соединения маршрутизирует команды через агентов
2. **CDP agent** — легковесный сервис на каждом стенде:
   - Принимает команды по HTTP/WebSocket (запустить Obsidian, выполнить JS, скриншот)
   - Управляет Obsidian через локальный CDP
   - Возвращает результаты (assertion pass/fail, скриншоты, логи)
3. **Connection layer** — SSH-туннель или WireGuard/VPN для безопасности

Альтернативный подход (проще): **Gauge на каждом стенде, результаты агрегируются централизованно**:
- Тесты и specs заливаются на стенд (git pull)
- Gauge запускается локально на стенде
- Результаты (JUnit XML, скриншоты) отправляются на хост для анализа

## Risks / unknowns

- CDP через сеть может быть медленным — тайминги в тестах нужно калибровать под latency
- Безопасность: открытый CDP-порт на удалённой машине — нужен SSH-туннель
- На Windows: как запускать Obsidian headless? Есть ли CDP в Windows-версии Electron?
- node-pty на Windows требует Visual C++ Build Tools для компиляции
- Нужен ли реальный дисплей на стенде или xvfb/виртуальный дисплей?
- Gauge может не поддерживаться на всех платформах одинаково
- Синхронизация версий плагина между стендами

## Notes

- Связано с идеей кросс-платформенного тестирования — remote bench это инфраструктурный enables для неё
- Возможно, проще начать с ручного подхода: Makefile-цели `test-macos`, `test-linux`, `test-windows`, которые цепляются к соответствующим стендам
