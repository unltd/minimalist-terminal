# User Feedback Loop — упрощённый сбор и обработка обратной связи

**Created:** 2026-07-27
**Status:** idea
**Effort:** M
**Related:** [[2026-07-27--shell-selection-settings]] [[2026-07-27--prepare-to-prod-roadmap]]

## What

Встроить в плагин механизм, позволяющий пользователю отправить обратную связь (баг, пожелание, впечатление) в один-два клика прямо из интерфейса терминала. На приёмной стороне — автоматическая структуризация входящего фидбэка через Claude: классификация, дедупликация, приоритизация, формирование issues/tasks/ideas.

## Why

На старте проекта первые пользователи — единственный источник реальных данных о том, что работает, что ломается и чего не хватает. Традиционный путь («пойди на GitHub, заведи issue, заполни шаблон») — высокий порог: ~1% пользователей его преодолевают. Если снизить трение до одного клика и пары строк текста, конверсия в фидбэк вырастет на порядок. А автоматическая обработка на стороне мейнтейнера превратит поток сырого фидбэка в структурированный бэклог.

## Rough sketch

### Канал отправки (в плагине)

- Кнопка «Send feedback» в Settings Tab (видно всегда, не нужно лезть в GitHub)
- Или: command palette → «Terminal: Send feedback»
- Открывается мини-форма:
  - Тип: Bug / Feature request / General impression (радиокнопки)
  - Текст (textarea, 2-3 строки минимум)
  - Email/GitHub username (опционально, для follow-up)
- Жмёт «Send» → JSON-пакет уходит в GitHub Issues (через GitHub API) или в Google Form / Discord webhook

### Обработка на стороне мейнтейнера

- Входящий фидбэк попадает в GitHub Issues с меткой `feedback`
- Claude-агент (в этом vault) периодически сканирует новые feedback-issue:
  1. Классифицирует: bug → `docs/bugs/`, feature → `docs/ideas/`, impression → `docs/ideas/`
  2. Дедуплицирует: `[[related-entry]]` если уже есть похожее
  3. Приоритизирует: на основе frequency × severity × effort
  4. Обновляет roadmap
- Человек только review'ит результат

### Альтернативы канала

| Канал | Плюс | Минус |
|-------|------|-------|
| GitHub Issues | Бесплатно, уже есть, API | Требует GitHub-аккаунт у пользователя |
| Google Form → Sheets | Не требует аккаунта, легко встроить | Нужен GCP key, настройка |
| Discord webhook | Мгновенно, community-friendly | Нужен Discord-сервер |
| Email (mailgun/sendgrid) | Самый низкий порог | Платно, сложнее автоматизация |

Предлагаю: начать с GitHub Issues (минимальный порог для мейнтейнера), потом добавить альтернативные каналы.

## Risks / unknowns

- Спам/мусорный фидбэк — нужна минимальная валидация (непустой текст, мин. длина)
- GitHub rate limiting если использовать API без токена
- Приватность: email пользователя в issue
- Нужно ли согласие на обработку? (GDPR и т.п. — для OSS-плагина вряд ли, но стоит подумать)
- Нужен ли public roadmap чтобы пользователи видели, что их фидбэк учтён?

## Notes

- Идея возникла при обсуждении Этапа 1 prepare-to-prod: как только плагин станет публичным, критически важен быстрый фидбэк-луп
