# Cross-Platform Testing Strategy

**Created:** 2026-07-20
**Status:** idea
**Effort:** L
<!-- **Related:** [[2026-07-20--mvp-test-plan]] -->

## What

Разработать план тестирования плагина на трёх целевых платформах: macOS, Linux, Windows. Экстраполировать текущий тестовый фреймворк (Gauge + pytest + CDP) на все OS.

## Why

Плагин движется к продакшену. Obsidian работает на macOS, Linux, Windows — каждая платформа имеет свои особенности:
- **macOS**: основная платформа разработки, уже покрыта тестами через CDP
- **Linux**: потенциально отличается поведение PTY, shell, файловых путей
- **Windows**: самая проблемная — нет PTY из коробки (winpty/conpty), другие shell (cmd, PowerShell, WSL), другие конвенции путей

Без систематического кросс-платформенного тестирования баги на Windows и Linux будут обнаруживаться пользователями, а не разработчиком.

## Rough sketch

Текущая структура тестов (`tests/`):
```
tests/
├── specs/mvp/          # Gauge .spec файлы (BDD-сценарии)
├── step_impl/          # Python реализация шагов (pytest + CDP)
├── env/default/        # Конфигурация окружения
└── logs/               # Gauge логи
```

План экстраполяции:
1. Выделить платформо-независимые тесты (build/load, открытие терминала, shell execution)
2. Определить платформо-специфичные сценарии:
   - Windows: conpty vs winpty, PowerShell vs WSL, CRLF в выводе
   - Linux: разные терминалы (gnome-terminal, konsole), /dev/pts
   - macOS: текущие тесты как baseline
3. Добавить платформенные теги в Gauge specs: `[macos]`, `[linux]`, `[windows]`
4. Создать платформенные профили в `env/`:
   ```
   tests/
   ├── env/macos/
   ├── env/linux/
   └── env/windows/
   ```

## Risks / unknowns

- Нет доступа к Windows-машине для разработки
- CDP может работать иначе или отсутствовать на некоторых платформах
- node-pty бинарно привязан к платформе — нужно тестировать реальную сборку, а не мок
- Gauge должен быть установлен на каждой тестовой машине
- Не все платформенные особенности можно поймать через CDP (например, проблемы с GPU-рендерингом)

## Notes

- Связано с идеей remote test bench — без удалённого доступа к Windows/Linux машинам кросс-платформенное тестирование невозможно
